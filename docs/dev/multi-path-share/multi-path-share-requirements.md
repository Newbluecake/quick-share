# 需求文档: 多路径分享 (Multi-Path Share)

> **功能标识**: multi-path-share
> **复杂度**: complex

## 1. 概述

### 1.1 一句话描述

支持 `quick-share` 同时传入多个文件和文件夹，接收方通过统一的文件列表页面浏览和下载。

### 1.2 核心价值

当前 quick-share 只能传入单个文件或单个文件夹，用户需要分享多个文件时必须先手动打包或多次启动。多路径分享让用户一条命令即可分享任意数量的文件和文件夹。

### 1.3 目标用户

局域网内需要快速分享多个文件/文件夹的开发者和普通用户。

### 2.2 验收标准

**R-001: CLI 多路径参数**
- WHEN 用户执行 `quick-share file1.txt file2.pdf ./docs` THEN 服务正常启动，分享所有传入的文件和文件夹
- WHEN 用户执行 `quick-share *.pdf ./docs` THEN shell 通配符自然展开，所有匹配文件被分享
- WHEN 用户传入不存在的路径 THEN CLI 报错并提示具体哪个路径不存在
- WHEN 用户未传入任何路径 THEN CLI 显示帮助信息（保持现有行为）

**R-002: 统一文件列表页面**
- WHEN 接收方访问分享 URL THEN 看到扁平列表页面，列出所有文件和文件夹
- WHEN 列表中有文件 THEN 显示文件名和文件大小
- WHEN 列表中有文件夹 THEN 显示文件夹名和文件夹图标，可点击展开

**R-003: 逐个下载**
- WHEN 接收方点击单个文件 THEN 直接下载该文件
- WHEN 接收方点击文件夹内的单个文件 THEN 直接下载该文件

**R-004: 全部打包下载**
- WHEN 接收方点击「全部打包下载」按钮 THEN 将所有文件和文件夹打包为 ZIP 流式下载
- WHEN ZIP 包含文件夹 THEN 文件夹内部结构在 ZIP 中保持不变

**R-005: 文件夹展开浏览**
- WHEN 接收方点击文件夹 THEN 展开显示文件夹内部内容
- WHEN 文件夹内有子文件夹 THEN 子文件夹也可继续展开

**R-006: 同名冲突检测**
- WHEN 用户传入 `./a/test.txt ./b/test.txt` THEN CLI 报错提示存在同名文件 `test.txt`
- WHEN 用户传入 `./a/docs ./b/docs` THEN CLI 报错提示存在同名文件夹 `docs`
- WHEN 同名文件来自不同目录 THEN 错误信息应显示完整路径帮助用户定位

**R-007: 单文件统一体验**
- WHEN 用户执行 `quick-share single.txt` THEN 显示文件列表页面（不再直接下载）
- WHEN 列表中只有一个文件 THEN 页面仍然显示列表视图和打包下载按钮

**R-008: 会话计数**
- WHEN 设置 `-n 3` THEN 最多允许 3 个不同会话访问
- WHEN 同一会话内下载多个文件 THEN 不额外消耗下载次数

## 4. 技术约束

### 4.1 技术栈

- Python 3.8+，仅使用标准库（保持现有约束）
- HTTP 服务基于 `http.server.ThreadingHTTPServer`
- 前端使用内嵌 HTML/CSS/JS（SPA 模式 + Legacy 模式）

### 4.2 集成点

- **CLI 层** (`src/cli.py`): `file_path` 参数从单值改为 `nargs='+'` 接受多值
- **入口层** (`src/main.py`): 路径验证逻辑需支持多路径，冲突检测在此层实现
- **服务层** (`src/server.py`): 新增 `MultiShareServer` 或复用/扩展 `DirectoryShareServer`
- **模板层** (`src/templates.py`): 文件列表页面适配多路径场景
- **安全层** (`src/security.py`): 路径验证需覆盖多路径场景

## 5. 排除项

- 不支持拖拽上传
- 不支持接收方文件选择器（选择性下载部分文件）
- 不支持访问权限控制（密码保护等）
- 不支持动态添加/移除分享文件（启动后固定）
- 不支持跨网段分享
