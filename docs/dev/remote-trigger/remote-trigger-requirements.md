# 需求文档: Quick Share 远程触发文件传输

> **生成方式**: 由 /devagent:dev-clarify 自动生成

## 1. 概述

为 quick-share 增加实例间远程触发文件传输能力，体验类似 **lszrz（sz/rz）**——一台 quick-share 实例可以通过 HTTP 请求触发另一台实例弹出系统原生文件浏览器，完成文件上传或下载。

**目标用户**:
- 开发者、运维工程师在两台机器间快速传输文件
- 远程服务器场景：一台机器运行 quick-share 作为常驻服务，另一台机器可随时触发它选择文件上传或指定保存路径

**核心价值**:
- 无需在两台机器上都手动操作，远程即可触发对端弹出文件浏览器
- 利用系统原生对话框，用户无需记忆文件路径
- 保持 quick-share 零外部依赖的理念，复用现有 HTTP 服务能力

## 2. 需求与用户故事

### 需求 1: 配置文件管理
**用户故事:** As a 用户, I want 通过配置文件指定要连接的远程 quick-share 实例, so that 启动时自动建立连接而不需要每次手动输入地址。

#### 验收标准（可测试）
- **WHEN** 用户执行 `quick-share config --peer 192.168.1.5:8080 --secret mykey`, **THEN** 系统 **SHALL** 将远程地址和共享密钥保存到配置文件。
- **WHEN** 用户执行 `quick-share config --show`, **THEN** 系统 **SHALL** 显示当前配置的远程实例地址和密钥（脱敏显示）。
- **IF** 配置文件不存在, **THEN** quick-share 启动时 **SHALL** 静默跳过远程连接。
- **IF** 配置文件存在且格式正确, **THEN** quick-share 启动时 **SHALL** 自动读取并连接远程实例。

### 需求 2: 启动时自动连接远程实例
**用户故事:** As a 用户, I want quick-share 启动时自动连接配置的远程实例, so that 无需额外操作即可让两台实例互通。

#### 验收标准（可测试）
- **WHEN** quick-share 启动且配置文件有效, **THEN** 系统 **SHALL** 向远程实例发送注册请求（含本机 IP、端口、共享密钥）。
- **IF** 远程实例响应成功, **THEN** 系统 **SHALL** 在终端显示连接成功提示（如 "已连接远程实例 192.168.1.5:8080"）。
- **IF** 远程实例不可达, **THEN** 系统 **SHALL** 显示警告但不中断本地 HTTP 服务启动。
- **IF** 共享密钥验证失败, **THEN** 系统 **SHALL** 显示错误提示并跳过连接。

### 需求 3: 远程触发上传（类似 rz）
**用户故事:** As a 远程用户, I want 触发对端 quick-share 弹出文件选择对话框, so that 对端用户可以选择文件上传给我。

#### 验收标准（可测试）
- **WHEN** 远程实例 B 向 A 发送上传触发请求（`POST /api/peer/request-upload`）, **THEN** A **SHALL** 在终端显示提示信息（如 "收到来自 192.168.1.5 的上传请求"）并弹出系统文件选择对话框。
- **WHEN** A 的用户在对话框中选择文件/目录后, **THEN** A **SHALL** 将选中的文件通过 HTTP 发送到 B。
- **IF** A 的用户取消文件选择对话框, **THEN** A **SHALL** 向 B 回复取消状态。
- **IF** 请求中未携带有效共享密钥, **THEN** A **SHALL** 返回 403 Forbidden。

### 需求 4: 远程触发下载（类似 sz）
**用户故事:** As a 远程用户, I want 触发对端 quick-share 弹出保存路径选择对话框, so that 我可以将文件发送到对端指定的路径。

#### 验收标准（可测试）
- **WHEN** 远程实例 B 向 A 发送下载触发请求（`POST /api/peer/request-download`，附带文件元信息）, **THEN** A **SHALL** 在终端显示提示信息（如 "收到来自 192.168.1.5 的文件传输请求"）并弹出系统保存路径选择对话框。
- **WHEN** A 的用户选择保存路径后, **THEN** A **SHALL** 向 B 确认并开始接收文件。
- **IF** A 的用户取消保存路径选择, **THEN** A **SHALL** 向 B 回复取消状态。
- **WHEN** 文件传输完成, **THEN** A **SHALL** 在终端显示传输完成信息。

### 需求 5: 实例间文件传输
**用户故事:** As a 用户, I want 文件在实例间可靠传输, so that 上传和下载都能正确完成。

#### 验收标准（可测试）
- **WHEN** 上传文件, **THEN** 系统 **SHALL** 使用分块流式传输（8KB 块），支持大文件。
- **WHEN** 传输目录, **THEN** 系统 **SHALL** 自动打包为 ZIP 流式传输。
- **IF** 传输过程中连接中断, **THEN** 系统 **SHALL** 在终端显示错误信息。
- **WHEN** 传输完成, **THEN** 系统 **SHALL** 在两端终端显示传输结果（文件名、大小）。

### 需求 6: 系统原生文件对话框
**用户故事:** As a 用户, I want 文件对话框使用系统原生 UI, so that 体验与本地应用一致。

#### 验收标准（可测试）

- **WHEN** 运行在 Linux + KDE 环境, **THEN** 系统 **SHALL** 使用 kdialog 弹出文件对话框。
- **WHEN** 运行在 macOS 环境, **THEN** 系统 **SHALL** 使用 osascript 弹出文件对话框。

- **IF** 系统没有可用的对话框工具, **THEN** 系统 **SHALL** 降级为终端交互模式（提示用户输入路径）。

### 需求 7: 共享密钥验证
**用户故事:** As a 用户, I want 通过共享密钥防止未授权的远程触发, so that 只有可信实例可以触发文件操作。

#### 验收标准（可测试）
- **WHEN** 远程请求包含 API 端点（`/api/peer/*`）, **THEN** 系统 **SHALL** 验证请求头中的 `X-Peer-Secret`。
- **IF** 密钥不匹配, **THEN** 系统 **SHALL** 返回 403 并记录警告日志。
- **IF** 未配置密钥, **THEN** 系统 **SHALL** 拒绝所有远程触发请求并返回 403。

## 4. 技术约束

### 4.1 技术栈
- **语言/框架**: Python 3.8+（与现有项目一致）
- **依赖**: Python 标准库（`http.server`, `http.client`, `json`, `subprocess`, `threading`）
- **系统工具**: zenity/kdialog/osascript/PowerShell（运行时检测）

### 4.2 集成点
- **新增模块**:
  - `src/config.py`: 配置文件读写管理
  - `src/peer_client.py`: 远程实例 HTTP 客户端
  - `src/peer_api.py`: 远程触发 API 端点处理
  - `src/file_dialog.py`: 跨平台系统对话框调用
- **修改模块**:
  - `src/cli.py`: 新增 `config` 子命令和相关参数
  - `src/server.py`: 注册 `/api/peer/*` 端点
  - `src/main.py`: 启动流程增加配置读取和远程连接

### 4.3 配置文件
- **位置**: `~/.quick-share/config.json`
- **格式**:
  ```json
  {
    "peer": {
      "address": "192.168.1.5:8080",
      "secret": "<shared-key>"
    }
  }
  ```

### 4.4 安全要求
- 远程触发 API 端点（`/api/peer/*`）必须验证共享密钥
- 密钥通过 HTTP 头 `X-Peer-Secret` 传递
- 未配置密钥时拒绝所有远程触发请求
- 不在日志中记录完整密钥

### 4.5 API 端点设计

| 端点 | 方法 | 说明 |
|------|------|------|
| `/api/peer/hello` | POST | 注册/握手，携带本机信息和密钥 |
| `/api/peer/request-upload` | POST | 请求对端选择文件上传 |
| `/api/peer/request-download` | POST | 请求对端选择保存路径 |
| `/api/peer/upload` | POST | 实际上传文件数据 |
| `/api/peer/download` | GET | 实际下载文件数据 |

## 5. 排除项

- **自动文件同步**: 不做自动化的文件同步/备份，每次传输需用户手动确认
- **NAT 穿透**: 两个实例必须在同一局域网或直接可达网络中，不涉及内网穿透
- **传输加密**: 依赖 HTTP，不做端到端加密（局域网环境）
- **断点续传**: 第一版不支持
- **传输队列**: 每次只处理一个传输请求，不排队
- **GUI 客户端**: 不做独立 GUI 应用，仅通过系统对话框交互
- **多跳中继**: 不支持通过第三方实例中转
