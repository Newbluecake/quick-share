# 需求文档: 上传功能

## 1. 概述

为 Quick Share 增加文件上传能力，使用户在分享文件的同时，接收方也能上传文件回来，实现**双向文件交换**。

- **核心价值**：从单向分享变为双向交换，覆盖「收集文件」「协作交换」等场景
- **目标用户**：需要在局域网内快速交换文件的开发者、设计师、团队协作者

## 2. 需求与用户故事

### R1: 独立上传模式

**用户故事**：作为发起方，我希望启动一个纯上传服务，让局域网内其他人能上传文件给我。

- `quick-share --upload [保存目录]` 启动纯上传服务
- 不指定目录时默认保存到当前工作目录
- 终端输出上传链接（curl 命令 + 浏览器 URL）
- 接受标准：
  - 对方通过浏览器可以访问上传页面并选择文件上传
  - 上传的文件正确保存到指定目录
  - 终端显示上传进度日志

### R2: 集成上传（分享页面上传入口）

**用户故事**：作为发起方，我在分享文件时希望对方也能上传文件回来。

- 在现有 SPA 文件浏览页面中增加「上传」按钮/区域
- 分享模式和上传模式共存，不互斥
- 接受标准：
  - 打开分享链接后，页面同时展示文件列表和上传入口
  - 上传和下载功能各自独立运行

### R3: 可选密码保护

**用户故事**：作为发起方，我希望设置上传密码，防止未授权的人上传文件。

- 新增 `--upload-password <password>` CLI 参数
- 上传前需验证密码（浏览器端输入或 HTTP 头传递）
- 下载功能不受密码影响
- 接受标准：
  - 设置密码后，未提供密码的上传请求被拒绝
  - 下载、浏览等现有功能不受影响

### R4: 上传限制与配额共享

**用户故事**：我希望上传和下载共享同一套限制策略，避免服务被滥用。

- 复用现有 `-n` / `-t` 参数，上传计入总操作次数
- 超时后服务自动关闭，无论上传还是下载
- 接受标准：
  - `-n 5` 时，3 次下载 + 2 次上传后服务关闭
  - `-t 5m` 时，超时后上传/下载均不可用

### R5: 文件名冲突自动重命名

**用户故事**：上传同名文件时不应覆盖已有文件，而是自动重命名。

- 冲突时自动添加序号后缀，格式：`filename (1).ext`、`filename (2).ext`
- 接受标准：
  - 上传 `report.pdf`，目录已有同名文件时保存为 `report (1).pdf`
  - 多次上传同名文件依次递增序号

### R6: 上传进度展示

**用户故事**：作为发起方，我希望在终端看到上传进度。

- 终端日志显示上传开始、进度、完成、中断/错误
- 与现有下载日志风格一致（含时间戳和状态标记）
- 接受标准：
  - 上传完成时终端显示文件名、大小、耗时

## 4. 技术约束

- 纯 Python 标准库实现（与项目现有约束一致）
- HTTP 上传使用 `multipart/form-data` 编码
- 上传端点：`POST /upload`
- 上传页面路由：`GET /upload`（独立模式）或 SPA 内集成
- 路径遍历防护沿用 `security.py` 的沙箱机制
- 文件大小无硬性限制（标准库限制内存，大文件自动写入临时文件）
- Vue 3 SPA 加载 cdnjs/marked 和 cdnjs/prism（与现有 SPA 一致）

## 5. 排除项

- 断点续传（本次不实现）
- 上传文件自动压缩/解压
- 上传后自动同步到其他设备
- HTTPS 支持（与项目现有范围一致，LAN HTTP）
- 用户认证体系（仅保留可选密码）
